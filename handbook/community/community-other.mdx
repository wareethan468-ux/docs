More tools groups the workflows below. More commands in this category.

## What this module does

- Create and manage custom command aliases
- Claim an unowned district for your crew

## Before you start

Agree on the audience before posting or changing shared records.

Individual actions can still check channel access, ownership and service authorization.

## Setup and access

This module has no dedicated entry in shared setup. Use its supported Discord workflows. The command browser provides exact inputs; one-time configuration tools may still exist outside /setup.

## Everyday workflow

1. Find the matching workflow in the command browser.
2. Supply the real member, record or channel.
3. Inspect the saved or posted result.

## Check the result

- Check visibility as a member.
- Use record identifiers when names are ambiguous.

## Troubleshooting

Check the target, destination and saved settings before repeating a mutation. Use the current browser inputs and the Troubleshooting guide for access, hierarchy and provider issues.

## Open shared setup

**Syntax and example**

```text
/setup
```

Choose the module using the menu; module names are not arguments to this command.

**Wrong**

```text
setup
```

Missing the slash. Select `/setup` from Discord’s command picker.

## Command syntax and examples

Templates show the expected argument structure, not literal values to send. These examples do not execute commands.

<AccordionGroup>

<Accordion title="!alias add">

Create an alias for a command

**Syntax**

```text
!alias add <alias> <command> [subcommand]
```

**Example template**

```text
!alias add alias:<alias> command:<command>
```

Replace angle-bracket placeholders with real values; omit square-bracket options you do not need. Quote text containing spaces. Use your server prefix if it differs from !.

**Wrong**

```text
!alias add
```

Missing `alias`, `command`.

</Accordion>
